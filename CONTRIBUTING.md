# Contributing to BAILE

Start with [README.md](README.md), [STATUS.md](STATUS.md) and [BUILDING.md](BUILDING.md).

## Reports

Include the BAILE commit, whether you used the portable host, browser preview, native emulator or physical FM-1, the steps, expected result and actual result. For installation reports include the previous firmware and the exact code on the device screen. Remove account identifiers and personal data from logs. Do not post instrument backups, credentials or private projects.

## Changes

Keep one active kit, Tamborzão as the default, PRESETS for kit selection, ALGORITHM for the selected drum part, K1 Saturator, K2 Reverb, K3 BPM and K4 Swing. Preserve existing controls and make additions incrementally. Clearly label provisional kit content.

Run the repository checks and portable tests. For board changes, provide separate physical evidence; do not use portable or emulator results as a hardware pass. Do not disable boot/migration checks to make an update appear successful.

The SDK is kept unchanged and hash-verified. If a change needs SDK work, discuss it first; the public APP source and the proprietary engine are different components. Follow the applicable notices in [LICENSING.md](LICENSING.md) and [THIRD_PARTY.md](THIRD_PARTY.md).
